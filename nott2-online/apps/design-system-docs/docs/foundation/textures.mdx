# Texture Library

Night of the Thirteenth uses photographic textures to make diegetic components feel *physical* — not flat colored boxes, but surfaces with grain, weight, and history. This page catalogues every texture asset in the system, its visual character, and where it's used.

Textures are the bridge between the clean digital foundation and the visceral horror aesthetic. They should be used sparingly and deliberately — a texture without purpose is visual noise.

---

## Delivery Methods

The system uses two different strategies for delivering textures, depending on where the component lives:

| Method | How It Works | When To Use |
|---|---|---|
| **Vite Asset Import** | `import texture from '../../assets/textures/file.png'` — bundled, hashed, treeshakeable | Components inside `@nott2/design-system` package (ResultBanner, DoomClock) |
| **Public URL** | `url(/textures/file.png)` — served from `apps/web/public/textures/` | Components that render only in the web app context (PlayingCard, CardMatt, SceneChallengeOverlay) |

:::note Why Two Methods?
The design system package is consumed by multiple apps (web, docs, storybook). Components that need textures in *all* contexts must bundle them via Vite imports. Components that only render in the main web app can reference `public/` URLs directly.
:::

## Usage Guidelines

### When to Use Textures

- **Diegetic components** that represent physical game props (cards, table felt, clock, banners)
- **Cinematic overlays** that need to feel like degraded film/VHS footage
- **Hero-level set pieces** where materiality adds narrative weight

### When NOT to Use Textures

- **UI chrome** — buttons, inputs, callouts, badges. These should be clean and functional.
- **Layout components** — stacks, rows, grids. These are invisible scaffolding.
- **Body text or labels** — textures on small text are illegible noise.

### Performance Considerations

- Textures are large files (600KB–1.2MB). They are a meaningful part of the initial bundle.
- Use Vite asset imports for design-system components — Vite will hash and optimize them.
- Public textures load on demand — ensure they're not on the critical rendering path.
- Always provide a `backgroundColor` fallback so the component renders correctly before the texture loads.

### Adding New Textures

1. **Choose delivery method** — bundle (if used in `@nott2/design-system`) or public (if web-app only)
2. **Target resolution** — textures should be high enough quality for retina (2x) but not excessively large. Aim for ~1024px on the longest side for tileable textures, full-width for banners.
3. **Visual consistency** — new textures must match the system's "weathered, physical, dark" aesthetic. No clean stock photos, no bright or cheerful surfaces.
4. **Document here** — add an entry to this page with visual character, blend mode, and consuming components.

:::caution
Never reference a texture by hardcoded path in a `.css.ts` file if the component is in the design-system package. Use a Vite import and pass the URL as an inline style or prop. This ensures the texture is available in all consumer contexts (web app, storybook, docs).
:::
