# Visual Identity

*This is not a SaaS design system. This is a horror film rendered as an interface.*

Night of the Thirteenth 2 borrows its visual grammar from slasher cinema, not from Material Design or Apple HIG. Every decision — from how a glow escalates to how a texture bleeds through type — serves the same goal: make the player *feel* like something is watching them from behind the screen.

This page establishes the five principles that govern every visual decision in the system. If a component looks wrong, one of these principles has been violated. If a new component needs designing, these principles are your brief.

---

## The Five Principles

### 1. Dark Canvas, Luminous Actors

The UI is a stage. The background is near-black (`#0a0a0a`), the surfaces are barely lighter (`#141414`, `#1a1a1a`), and the *elements themselves* are the light sources. There are no traditional drop shadows in the system — no floating Material cards, no gentle elevation hierarchy. Instead, every interactive element **radiates light**, as if something beneath the surface is alive.

This is the single most important visual distinction. Most design systems use shadow to create depth. We use it to create **presence** — the feeling that what you're looking at has weight, heat, intent.

**The rule:** If you're reaching for `box-shadow` to create depth/elevation, stop. Use a glow token instead. Elements don't float above the page — they burn through it.

Nothing in a slasher film is mathematically precise. Blood doesn't pool in perfect circles. Walls don't crack along grid lines. The same applies here — key components use `clip-path: polygon(...)` with deliberately imperfect coordinates, subtle `transform: rotate(-1deg)` tilts, and gradient bleeds that fade unevenly.

This doesn't mean everything is skewed. **Atoms** (buttons, text, badges) are precise and functional. **Molecules and organisms** that represent narrative moments (ResultBanner, DoomClock, ActBreakOverlay) embrace imperfection — they are the set pieces of the horror film.

**The rule:** Functional UI should feel stable and predictable. Narrative UI should feel *slightly* wrong — like the walls are closing in.

    <span style={{ fontFamily: "'Playfair Display', Georgia, serif", fontSize: '0.75rem', color: '#dc2626', textTransform: 'uppercase', letterSpacing: '0.12em', fontWeight: 700 }}>Lethal</span>

Color in this system is temperature. Not decorative, not categorical — *thermal*. The palette maps to a four-step temperature gradient that every player internalises after five minutes of play:

| Temperature | Color | Emotional Register | Example |
|---|---|---|---|
| **Cold (Safe)** | Green | Relief, survival, reprieve | Trophy earned, weakness discovered |
| **Warm (Strained)** | Amber | Caution, the machine grinding | Failed number challenge, escalation |
| **Hot (Breaking)** | Orange | Physical cost, body screaming | Overexertion, high-effort actions |
| **Lethal** | Red | Death, the Killer, finality | Strikes, face cards, elimination |

This isn't an abstract colour chart — it's a *thermometer*. When the EffortBand turns from green to amber to orange to red, the player doesn't need to read the label. They feel the heat rising.

**The rule:** Every color application must map to a temperature. If you're choosing a color for aesthetic reasons, you're choosing wrong.

Some components in this system are **diegetic** — they represent physical objects that exist in the game world. The card table is covered in red velvet. Playing cards are printed on aged parchment. The doom clock is made of weathered iron. These aren't metaphors; they're material simulations.

Diegetic components use photographic textures, `mix-blend-mode`, and `background-image` layering to achieve a tactile, physical quality. The textures are documented in the [Texture Library](/foundation/textures) and live in the assets directory.

Non-diegetic components (buttons, callouts, layout primitives) stay clean and functional. The tension between the two — the sterile UI *around* the visceral game objects — is itself a design choice. It mirrors the framing of a horror film: the camera (UI) is clinical and steady, even while the scene it's capturing is violent.

**The rule:** If a component represents a physical game prop, it should look like that prop — felt, parchment, iron, blood. If it represents UI chrome, it should be minimal and invisible.

### 5. Cinematic Pacing

Motion in the system borrows from film language. There are no bouncy animations, no playful overshoots, no "delightful" micro-interactions. Instead:

| Film Technique | UI Equivalent | Example |
|---|---|---|
| **The Held Breath** | Slow `ease-in-out` breathing loops (2–4s) | DoomClock pulse, beacon glow |
| **The Slow Pan** | `400ms ease-out` transitions | Clock hand sweep, card table border |
| **The Jump Cut** | `150ms ease-out` micro-transitions | Tab switches, button hovers |
| **The Jump Scare** | One-shot cinematic animations with shake | SceneChallengeOverlay, ActBreakOverlay |
| **The Accelerating Heartbeat** | Animation speed increases with danger | EffortBand: 3s → 2.5s → 2s pulse |

**The rule:** Every animation must feel like a camera technique. If it feels like a productivity app transition, it's wrong. If it feels like a children's game bounce, it's very wrong.

## The Three Layers

The visual language operates at three scales. Each layer has different rules:

```
┌──────────────────────────────────────────────┐
│                  SET PIECES                  │
│   DoomClock · ResultBanner · ActBreakOverlay │
│         Bespoke, cinematic, textured         │
├──────────────────────────────────────────────┤
│              VOCABULARY                      │
│    Edge Bleed · Inset Wound · Gradient Wash  │
│    Reusable compositional patterns           │
├──────────────────────────────────────────────┤
│                FOUNDATION                    │
│   Colors · Typography · Spacing · Glows      │
│           Tokens and primitives              │
└──────────────────────────────────────────────┘
```

| Layer | What It Contains | How Strictly It's Enforced |
|---|---|---|
| **Foundation** | Tokens (`vars.*`), type scale, spacing grid, glow escalation | **Absolute** — no exceptions, no hardcoded values |
| **Vocabulary** | [Compositional patterns](/foundation/patterns) — the edge bleed, gradient wash, inset wound, etc. | **Strong convention** — use these patterns when building new molecules; deviate only with justification |
| **Set Pieces** | Bespoke cinematic components with unique animations, textures, and layouts | **Guided by principles** — the five principles above, not rigid rules |

:::tip Where Does My Component Fit?
If you're building an **atom** (button, text, badge), you operate purely at the Foundation layer. If you're building a **molecule** (game widget), you should be using Vocabulary patterns on top of Foundation tokens. If you're building an **organism** (full-screen overlay, cinematic transition), you're in Set Piece territory — the principles guide you, but you have creative freedom.
:::

## Quick Reference: The Do / Don't Cheat Sheet

| Principle | ✅ Do | ❌ Don't |
|---|---|---|
| **Dark Canvas** | Use glow tokens for emphasis | Use `box-shadow` for Material-style elevation |
| **Imperfection** | Use `clip-path` and slight rotations on banners | Apply to buttons or form elements |
| **Semantic Heat** | Map every color to the temperature gradient | Choose colors for "variety" or aesthetics |
| **Diegetic Texture** | Use photographic textures for game props | Apply textures to UI chrome (buttons, cards, callouts) |
| **Cinematic Pacing** | Use `ease-out` for transitions, `ease-in-out` for breathing | Use `bounce`, `elastic`, or `linear` easing |
