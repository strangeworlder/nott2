# DiceResult

The verdict after the dice have spoken. One massive amber number flanked by two die-shaped silhouettes. The total radiates warmth; it IS the component. The d10 diamond and d4 pyramid are quiet evidence tokens orbiting the central truth. No plus signs, no equals signs — the spatial relationship implies the math. You see the number before you read anything else. That's the point.

<details open>
<summary>Code example</summary>

```tsx
import { DiceResult } from '@nott2/design-system';

<DiceResult d10={7} d4={3} />
```
</details>

## Why to Use

`DiceResult` is the most-viewed UI state in the game. After the dice have settled, this component presents the clinical breakdown of what happened. Rather than showing raw arithmetic (`7 + 3 = 10`), it uses spatial composition — the total dominates the center, flanked by `DieChip` atoms that carry their die identity through geometric silhouettes (diamond for d10, pyramid for d4).

## When to Use

> **Do**
> - Use as the primary display immediately after a player has committed their effort and threat rolls.
> - Provide `modifier` and `originalD4` when an Aptitude alters the d4 roll.
> - Provide `d10Modified` and `originalD10` when a Genre Point Reroll alters the d10.

> **Don't**
> - Do not use this component to declare success or failure. This component is just the math; use `ResultBanner` for the verdict.
> - Do not use raw numbers or `Text` atoms for die results. Always compose through `DiceResult` to maintain visual consistency.

## Anatomy

```
 ┌────────────────────────────────────────────────────┐
 ┃                                                     │
 │    ◇        │       10       │       △              │
 │   D10       │                │      D4              │
 │             │                │                      │
 └────────────────────────────────────────────────────┘
 ↑      ↑      ↑        ↑       ↑       ↑
 │  DieChip  divider   total  divider  DieChip
 left-edge bleed (::before, amber pulse)
 ─────────── bottom-edge gold glow (box-shadow) ───────
```

1. **Root** (`resultRoot`) — Flex row with centered alignment. Radial amber glow emanating from center. Left-edge amber bleed bar with pulsing animation. Bottom gold `box-shadow` glow.
2. **d10 DieChip** — Diamond silhouette on the left. Shows the threat die result.
3. **Divider** (`divider`) — 1px vertical amber gradient line separating the chips from the total.
4. **Total** (`totalNumber`) — The hero number. `clamp(2.5rem, 5vw, 3.5rem)` display font in `goldBright`. The visual anchor of the entire component.
5. **d4 DieChip** — Pyramid silhouette on the right. Shows the effort die result with optional modifier label.

## Behavior

- **Auto-calculated total**: The total is computed internally as `d10 + d4`. There is no `total` prop — the component owns its own arithmetic.
- **Amber glow theme**: The entire component uses a warm amber color palette (gold tones) rather than the red/green used elsewhere. This positions the result as *evidence* — neutral and factual — rather than verdict (which is `ResultBanner`'s job).
- **Left-edge bleed**: A 3px pulsing amber bar on the left edge (identical pattern to `DifficultyBadge`), tying the two components into the same visual family of "pre-verdict" UI.
- **Responsive total**: The center number uses `clamp(2.5rem, 5vw, 3.5rem)` to scale smoothly across viewport sizes.
- **Dual modification support**: Both dice can be independently modified — d4 via Aptitude (`modifier` + `originalD4`) and d10 via Genre Point Reroll (`d10Modified` + `originalD10`).

## Accessibility

- Uses `role="status"` with `aria-label` announcing the full roll (e.g., "Roll result: d10=7, d4=3, total=10").
- Each `DieChip` has its own `aria-label` providing detailed per-die information (e.g., "D4: 4 (was 3)").
- The dividers are marked `aria-hidden="true"` as decorative structural elements.
- The left-edge pulse animation respects `prefers-reduced-motion: reduce`.
