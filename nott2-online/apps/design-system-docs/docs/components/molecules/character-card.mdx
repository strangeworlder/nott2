# CharacterCard

A single player's status on the stage. It combines their identity, suffering (strikes), luck (genre points), and readiness (Ace token) into a single, cohesive block.

<details open>
<summary>Code example</summary>

```tsx
import { CharacterCard } from '@nott2/design-system';

<CharacterCard
  name="Alex"
  suit="Spades"
  strikes={1}
  genrePoints={2}
  isActive={true}
  hasAceToken={true}
/>
```
</details>

## Why to Use

The CharacterCard encapsulates all of a player's vital statistics into one dense, highly readable component. It takes atomic and molecular indicators (`PlayerAvatar`, `StrikeIndicator`, `Badge`, `PlayingCard`) and orchestrates them into a unified status card. 

Crucially, **CharacterCard is a presentational container, not an interactive button**. The game's flow dictates who is in the spotlight (the active player), not the player's clicks. 

## When to Use

> **Do**
> - **In application code**, always use `CharacterCard` inside the `CharacterBar` organism to render the array of players.
> - Pass all relevant state (strikes, GP, Ace tokens) downward into this molecule.

> **Don't**
> - **Never** wrap `CharacterCard` in a `<button>` or attach `onClick` handlers to it to drive game state. It is a mirror of the game state, not a controller.
> - Don't use `CharacterCard` outside of footer/bar contexts where its dense vertical layout might look out of place. Use `PlayerPanel` for larger contextual areas.

## Anatomy

```
 ┌──────────────────────┐
 │  ┌───┐               │
 │  │ A♠│      [AVATAR] │
 │  └───┘               │
 │            O  O  O   │
 │                      │
 │             2 GP     │
 └──────────────────────┘
      ▲           ▲
  Ace Token    Inner Stack
```

1. **Ace Token** — A micro `PlayingCard` showing the player's suit. It represents their turn order readiness.
2. **Inner Stack** — A vertically centered layout containing the `PlayerAvatar`, `StrikeIndicator`, and optional Genre Points `Badge`.

## Key Props

### `name` & `suit`
The core identity. Passed directly to the internal `PlayerAvatar`.

| Type | Default | Description |
|---|---|---|
| `string` | — | **Required.** The player's display name. |
| `string` | — | **Required.** The player's assigned suit. |

### `strikes` & `isDead`
The player's physical/mental toll. Passed to the `StrikeIndicator`. `isDead` takes ultimate priority.

| Type | Default | Description |
|---|---|---|
| `0 \| 1 \| 2 \| 3` | — | **Required.** The number of strikes. |
| `boolean` | `false` | When true, greys out the entire card and shows the death skull. |

|---|---|---|

## Behavior

- The `CharacterCard` is entirely presentational and devoid of interaction states (no `cursor: pointer` or `:hover` borders).
- `isDead` applies `opacity: 0.4` to the entire card layout.
- If `hasAceToken` is false, the card horizontally shrinks to its minimum width since the left Ace Token slot collapses.
