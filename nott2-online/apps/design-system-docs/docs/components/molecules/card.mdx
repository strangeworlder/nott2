# Card

The surface on which the game's content rests — a diegetic piece of dark wood or aged paper. Card creates depth and separation, grouping related mechanics into a single visual unit.

:::caution
This is a **UI container** component — not a playing card. For the diegetic card face (suit + rank), see [PlayingCard](/components/molecules/playing-card).
:::

## Why to Use

Card replaces raw `<div>` grouping with a semantically meaningful container that carries consistent padding, borders, backgrounds, and interactive states from the design system.

## When to Use

- **Grouping related content**: Instructions, results, player info
- **Emphasizing content**: Use `highlighted` or `instruction` variants
- **Showing outcomes**: `success` or `failure` variants
- **Layout-only grouping**: `ghost` variant (invisible container)

## Writing & Content Guidelines

- Card titles should be short noun phrases: "Scene Setup", "Roll Result"
- Use the `title` prop for the built-in h3 header — don't render your own heading inside a card

## Anatomy

```
┌─ border (variant-colored) ─────────────────┐
│                                             │
│  [Title]  ← optional h3 via title prop      │
│                                             │
│  Children content                           │
│  (any React nodes)                          │
│                                             │
└─────────────────────────────────────────────┘
```

## Key Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `variant` | `CardVariant` | `'default'` | Visual style |
| `title` | `string` | — | Optional h3 header |
| `interactive` | `boolean` | `false` | Hover glow + lift effect |
| `noPadding` | `boolean` | `false` | Remove internal padding |

## Behavior

- `interactive` adds a hover glow and subtle transform on mouseover.
- `noPadding` removes all internal padding — useful for cards containing full-bleed content like images or custom layouts.
- The `title` prop renders an h3 with the `cardTitle` style — styled consistently across all variants.

## Accessibility

- Card is a `<div>` container — no implicit role. Content inside determines semantics.
- If `interactive` is true, consider adding `role="button"` and keyboard handlers to the card.

## API Reference

### CardVariant

| Value | Background | Border | Use |
|---|---|---|---|
| `default` | `surface` | `border` | General grouping |
| `muted` | `background` 70% | `border` | De-emphasized |
| `highlighted` | `surfaceElevated` | `borderActive` (red) | Selected/important |
| `success` | `surface` | `success` (green) | Positive outcome |
| `failure` | `surface` | `accentBright` (red) | Negative outcome |
| `instruction` | Red-tinted transparent | `accent` | Game instructions |
| `ghost` | Transparent | None | Layout-only |
