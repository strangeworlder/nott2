# StatusCallout

The game's stage directions — system messages that tell the player what is happening, what just happened, or what they need to do next. Each variant carries a different emotional temperature, but they share a common voice: calm, precise, and in-world. They do not shout. They observe and instruct.

StatusCallout is the workhorse of the game's feedback system. During a single FalloutScreen resolution, a player might see 4–6 callouts in sequence — each one narrating a different mechanical consequence of their dice roll. This is the component that *explains the rules as they happen*.

<details open>
<summary>Code example</summary>

```tsx
import { StatusCallout } from '@nott2/design-system';

<StatusCallout variant="danger">
  <strong>Host</strong> has taken a Strike.
</StatusCallout>
```
</details>

## Why to Use

A tabletop roleplaying game relies on the Game Master to narrate consequences, explain rules, and guide the flow of play. In this digital companion, StatusCallout acts as the mechanical GM. It provides a standardized, diegetic voice that players trust to tell them what just happened and what they must do next. By using consistent semantic coloring, it trains the player to instinctively recognize the severity of an event (e.g., green for victory, red for pain, purple for instruction) before they even read the text.

## When to Use

Use StatusCallout whenever the game engine needs to speak directly to the player to explain a state change or prompt an action.

> **Do**
> - Use StatusCallout for narrative instructions like designating the Active Player.
> - Use it to narrate the mechanical fallout of a challenge (e.g., cards shuffling, difficulty changing).
> - Match the variant to the emotional tone (e.g., `highlight` for instructions, `danger` for Strikes).

> **Don't**
> - Don't use it for 1–3 word status tags — use [Badge](/components/atoms/badge) instead.
> - Don't use it for dramatic roll outcomes — use [ResultBanner](/components/molecules/result-banner) (that's the cinematic moment, not a stage direction).
> - Don't use it for body text or general descriptions — use [Text](/components/atoms/text).
> - Don't use it for a single icon without text — use [Icon](/components/atoms/icon) directly.

## Anatomy

```
┌─────────────────────────────────────────────┐
│ [Icon?]  Message content                     │  ← 1px all-around border
│          (any React children)               │  ← tinted background
└─────────────────────────────────────────────┘
```

The border and background tint are determined by the variant. The icon is optional and rendered at 18px. Children are wrapped in a flex-1 container so they fill the remaining width.

The base typography uses the **display font** at `label` size with `600` weight — the same font family as headings and badges, giving callouts an authoritative, premium feel. No `uppercase` transform is applied (unlike `Badge` or `Text variant="label"`) because callout content is prose, not a tag.

## Key Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `variant` | `'info' \| 'warning' \| 'danger' \| 'success' \| 'highlight'` | `'info'` | Semantic color — choose based on what happened, not what color you want |
| `icon` | `IconName` | — | Optional icon prepended to content. Use icons from the [Icon vocabulary](/components/atoms/icon) |
| `children` | `ReactNode` | — | Callout content — text, inline icons, `<strong>` tags |
| `id` | `string` | — | HTML id attribute |

## Content Guidelines

> **Do**
> - Keep messages concise (1–2 sentences max).
> - Write in a consistent "stage direction" voice (the narrator telling you what happened).
> - Use `<strong>` for emphasis on key game terms (deck names, character names, suit names).

> **Don't**
> - Don't use exclamation marks — the color carries the urgency ("A Weakness has been found" not "A Weakness has been found!").
> - Don't mix voices (e.g., don't jump from objective narrator to in-character dialogue).

## Behavior

- Renders with `role="status"` for screen reader announcement.
- The icon is rendered via the `<Icon>` component at 18px size.
- All five variants use a 1px solid border on all four sides with a subtle background tint. There is no left-border-only styling.

## Accessibility

- `role="status"` makes the element a live region — screen readers announce new callouts automatically.
- Always combine an icon with text. Never rely on color alone.
- In the FalloutScreen, multiple callouts are rendered in sequence — each is a separate `role="status"` element, so they are announced individually.

## API Reference

### CalloutVariant

| Value | Border / Background | Semantic Role | Typical Icons |
|---|---|---|---|
| `info` | Blue-tinted (hardcoded RGBA) | Neutral bookkeeping — what the machine is doing | `movie`, `shuffle`, `input`, `delete` |
| `warning` | Amber-tinted (`warning` token) | Escalation — something got worse, but nobody died | `warning`, `arrow_downward`, `dangerous` |
| `danger` | Red-tinted (`accentBright` token) | Pain — a Strike, a death, a loss | `bolt`, `dangerous` |
| `success` | Green-tinted (`success` token) | Progress — a threat removed, a trophy earned | `emoji_events`, `delete`, `key` |
| `highlight` | Purple-tinted (hardcoded RGBA) | Attention — an instruction, a special event, a rare moment | `playing_cards`, `auto_awesome`, `person_raised_hand`, `military_tech` |

:::note
`info` and `highlight` use hardcoded RGBA colors because blue and purple are UI-only — they are not part of the brand token contract. Red, amber, and green have corresponding tokens.
:::
