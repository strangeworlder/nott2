# Night of the Thirteenth — Design System

*The visual language of survival horror.*

This is the documentation for the **@nott2/design-system** package — the shared component library and design token system that powers every screen in *Night of the Thirteenth 2*. If you're building UI for the game, this is your reference.

**Who this is for:** Developers building features and screens for the NotT2 web application. You'll find design tokens, React components, usage patterns, and the rules that keep the interface consistent.

---

## Quick Start

Install from the monorepo root, then import and use:

```bash
# From the nott2-online root
npm install
```

```tsx
import { Text, Button, Card, Stack } from '@nott2/design-system';

function MyScreen() {
  return (
    <Stack gap="lg">
      <Text variant="h2">Scene Setup</Text>
      <Card variant="instruction">
        <Text>Draw a card from the threat deck.</Text>
      </Card>
      <Button variant="primary">Draw Card</Button>
    </Stack>
  );
}
```

## The Three Rules

Every contributor to the UI must follow these. They are non-negotiable.

### 1. No Raw HTML

Every visual element has a design system component. Use it. Raw HTML leaks browser defaults and breaks theming.

```tsx
// ❌ Don't — browser default, unthemeable
<h2>Scene Setup</h2>
<p>Draw a card from the threat deck.</p>
<div style={{ padding: 16 }}>...</div>

// ✅ Do — design system components, fully themed
<Text variant="h2">Scene Setup</Text>
<Text>Draw a card from the threat deck.</Text>
<Card>...</Card>
```

| Instead of… | Use… |
|---|---|
| `<p>`, `<h1>`, `<span>` | `<Text>` with `variant` prop |
| `<button>` | `<Button>` with `variant` prop |
| `<div>` for content grouping | `<Card>` with `variant` prop |
| `<hr>` | `<Separator>` |
| Inline SVGs | `<Icon name="...">` |

### 2. Tokens, Not Values

Never hardcode colors, fonts, or spacing. Components reference `vars.*` tokens from the [theme contract](/patterns/theme-contract), which means a playset can completely re-skin the game without touching a single component.

```tsx
// ❌ Don't — hardcoded, breaks when playset changes
const myStyle = style({
  color: '#e8e8e8',
  backgroundColor: '#141414',
  padding: '16px',
});

// ✅ Do — token-driven, playset-safe
const myStyle = style({
  color: vars.color.text,
  backgroundColor: vars.color.surface,
  padding: vars.space.md,
});
```

### 3. Props, Not Classes

Control component appearance through props, not utility classes. This keeps the theming contract intact and ensures playsets can override visual behavior.

```tsx
// ❌ Don't — utility classes bypass the design system
<Text className="font-bold text-red-400">Warning</Text>

// ✅ Do — props are the API
<Text variant="label" color="red">Warning</Text>
```

:::tip Golden Rule
If you're reaching for a CSS class, an inline style, or a raw HTML element — stop and check the design system first. There's almost certainly a component or token for what you need.
:::

## Architecture at a Glance

The system follows **atomic design** — small, single-purpose pieces compose into larger, game-aware structures:

| Layer | Purpose | Examples |
|---|---|---|
| **Atoms** | Pure UI primitives — no game knowledge | Text, Button, Icon, Badge, Stack, Row |
| **Molecules** | Single-purpose game widgets — composed from atoms | Card, PlayingCard, DoomClock, ResultBanner |
| **Organisms** | Full screen sections — compound compositions | GameBoard, PhasePanel, Header, ChatPanel |

Atoms know nothing about the game. Molecules know about one game concept (a card, a clock, a result). Organisms orchestrate multiple molecules into a full screen experience.

## Technology

| Concern | Tool |
|---|---|
| **Styling** | [Vanilla Extract](https://vanilla-extract.style/) — zero-runtime CSS-in-TypeScript |
| **Variants** | `@vanilla-extract/recipes` — type-safe variant-driven component styles |
| **Theming** | Contract-based (`createThemeContract` + `createTheme`) — playsets override tokens, not components |
| **Framework** | React 18/19, TypeScript strict mode |
| **Testing** | Vitest + @testing-library/react |
| **Docs** | This site (Docusaurus) + Storybook |
